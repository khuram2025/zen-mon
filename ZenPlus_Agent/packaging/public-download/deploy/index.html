Deploy ZenPlus Agent at scale

2. Silent install

Run as SYSTEM or from an elevated prompt. Replace the appliance address with yours.

EXE · server monitoring
zenplus-agent-core-x.y.z.exe /machine /quiet /norestart CONTROLLER_URL=https://zenplus.example.com INSTALL_PROFILE=infrastructure /log "C:\Windows\Temp\ZenPlusAgent-install.log"
MSI · server monitoring
msiexec /i zenplus-agent-core-x.y.z.msi /qn /norestart CONTROLLER_URL=https://zenplus.example.com INSTALL_PROFILE=infrastructure /L*v "C:\Windows\Temp\ZenPlusAgent-install.log"
EXE · server monitoring + APM
zenplus-agent-x.y.z.exe /machine /quiet /norestart CONTROLLER_URL=https://zenplus.example.com INSTALL_PROFILE=combined /log "C:\Windows\Temp\ZenPlusAgent-install.log"
MSI · server monitoring + APM
msiexec /i zenplus-agent-x.y.z.msi /qn /norestart CONTROLLER_URL=https://zenplus.example.com INSTALL_PROFILE=combined /L*v "C:\Windows\Temp\ZenPlusAgent-install.log"

Upgrades use the same command: an installed agent keeps its identity, credential, configuration and profile unless you pass a new one.

3. Switches and properties

Switch or propertyMeaning
/machine (/allusers)All-users installation with the Windows service. Use this for servers.
/user (/currentuser)Current-user installation without the service, for evaluation.
/quiet (/silent, /verysilent, /S, /qn)No user interface.
/norestartAccepted for compatibility. Setup never restarts Windows.
CONTROLLER_URL= (/controller-url)Appliance address. Required on a first install; an upgrade keeps the saved one unless given.
INSTALL_PROFILE= (/profile)infrastructure, combined or apm. A first install defaults to infrastructure; an upgrade keeps the installed profile.
CONTROLLER_CA_FILE= (/controller-ca-file)PEM bundle for an appliance certificate issued by a private CA. TLS verification stays on.
/log <path> (EXE) · /L*v <path> (MSI)Write Setup's log. The folder must exist.
/no-start-menuSkip the Start Menu shortcut.
/uninstall · /purge (PURGE=1)Remove the agent; with purge, also its data. See Uninstall.

Switches are case-insensitive and accept / or -. Unknown switches and properties are rejected (exit code 1639) rather than ignored. The server-monitoring package refuses the combined and apm profiles, and refuses to replace an installation whose applications are instrumented by APM.

4. Exit codes

Setup uses Windows Installer exit codes, which deployment tools already understand.

CodeMeaningAction
0Installed, upgraded or removedNone
1618Another ZenPlus installation is running, for example a self-updateRetry later. Intune and Configuration Manager do this automatically.
1639Invalid switch, property or profile for this packageFix the command line
740Not elevatedRun as SYSTEM or an administrator
1603Installation failed and was rolled backRead the log file
A failed installation or upgrade is rolled back automatically: the previous version, its configuration and the Windows service are restored. Exit codes other than 0 and 1 require agent 1.14.2 or later; earlier versions return 1 for every failure.

Group Policy

Use a computer startup script (runs as SYSTEM) that installs from a file share when the agent is missing:

PowerShell startup script
$key = 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\ZenPlus Agent'
if (-not (Test-Path $key)) {
  $p = Start-Process '\\fileserver\software\zenplus-agent-core-x.y.z.exe' -Wait -PassThru -ArgumentList @(
    '/machine', '/quiet', '/norestart',
    'CONTROLLER_URL=https://zenplus.example.com', 'INSTALL_PROFILE=infrastructure',
    '/log', 'C:\Windows\Temp\ZenPlusAgent-install.log')
  exit $p.ExitCode
}

You can also assign the MSI with Group Policy Software Installation, setting CONTROLLER_URL and INSTALL_PROFILE in a transform.

Configuration Manager (MECM / SCCM)

Create an application with a Script Installer deployment type. Use the install and uninstall commands above, detect with the same registry value, and set installation behavior to Install for system. Return code 1618 is a Fast retry by default.

PDQ Deploy and remote PowerShell

PDQ Deploy: add an Install step with the EXE and the silent parameters above; success code 0.

PowerShell remoting across many servers
$servers = Get-Content .\servers.txt
Invoke-Command -ComputerName $servers -ThrottleLimit 20 -ScriptBlock {
  $p = Start-Process '\\fileserver\software\zenplus-agent-core-x.y.z.exe' -Wait -PassThru -ArgumentList @(
    '/machine', '/quiet', '/norestart', 'CONTROLLER_URL=https://zenplus.example.com',
    'INSTALL_PROFILE=infrastructure', '/log', 'C:\Windows\Temp\ZenPlusAgent-install.log')
  [pscustomobject]@{ Server = $env:COMPUTERNAME; ExitCode = $p.ExitCode }
}

Install straight from the appliance

Without a file share, each server can download from your ZenPlus appliance. The script checks the SHA-256 and the Zentryc LLC signature, then exits with Setup's exit code. Run it in an elevated PowerShell:

PowerShell
$s = Join-Path $env:TEMP 'zenplus-agent-install.ps1'
Invoke-WebRequest -UseBasicParsing -Uri 'https://zenplus.example.com/api/v1/agents/install.ps1' -OutFile $s
& $s -ControllerUrl 'https://zenplus.example.com' -InstallProfile infrastructure

The same command, filled in for your appliance, is in the appliance's Install agent dialog.

Uninstall

Remove the agent
"%ProgramFiles%\ZenPlus\Agent\ZenPlusAgentSetup.exe" /uninstall /quiet

Add /purge to also delete %ProgramData%\ZenPlus\Agent (queued data, identity and logs). Uninstall first restores any applications ZenPlus instrumented for APM.

Approve and manage centrally

Approve in one stepIn Agent Fleet, filter Pending authorization, select all, and choose Authorize. Each agent receives its own credential, protected with Windows DPAPI.
Upgrade from the applianceTrigger upgrade installs a published version on the selected agents and shows progress for each one.
Add or remove APMChange monitoring profile installs the APM package or the server-monitoring package. Instrumented applications are restored first, with your consent.
Policies and ringsApply collection policies and update rings to groups of agents from Agent Fleet.

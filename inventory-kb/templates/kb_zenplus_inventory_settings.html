ZenPlus Inventory

Inventory settings

Five numbers, one switch and one list control how Inventory judges freshness, how long it remembers changes and what the software catalog leaves out. This article lists every setting, its limits and what changes when you save.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Administrators Reading time ~5 min

01 Where to find it, and who can change it #

Inventory & Compliance → Inventory Settings has one tab in this release, Data & retention. This release has no catalog rules, lifecycle overrides or saved views.

  • The sidebar row and the tab appear for every role with inventory.view. Changing a setting needs inventory.manage: a role with only inventory.view sees the same values read-only, with the note You can read these settings but not change them and the permission named. A role without any Inventory permission sees the access-denied page.
  • The settings are appliance-wide. They are not tag-scoped: a manager limited to some tags changes the same values everyone else sees.

02 Freshness targets #

These decide when the Fresh, Aging and Stale badges change. See health and freshness.

SettingUnitRangeDefaultEffect
Servers are fresh forhours1 to 72024A server whose last inventory is newer than this is Fresh
Network devices are fresh forhours1 to 7202The same for network devices
Stale afterdays1 to 3657Between the fresh target and this, an asset is Aging; older than this it is Stale

A fresh target can never be longer than the stale limit (stale days × 24 hours); if you ask for more, it is reduced to that and the save message says so. A line under the fields restates the rule in words with your numbers, for example A server is Fresh for 24 h after its last inventory, then Aging, and Stale after 7 days.

Assets that cannot report an inventory by design (a ping-only device, a server monitored without the Windows agent) are not judged by these targets: they read Not reported by design.

Match the server target to the interval of the agents. By default an agent sends its inventory every 6 hours (the setting collectors.inventory.interval_seconds in the agent’s own configuration file, not a field of Agent Policies), and 24 hours leaves room for three missed reports. If you lengthen the interval beyond the target, servers will flicker to Aging.

03 History and trends #

SettingUnitRangeDefaultEffect
Keep change history fordays30 to 3,650400Changes older than this are deleted by a daily clean-up. 400 days covers a twelve-month audit window with margin. Shortening it deletes data at the next clean-up
Daily snapshot athour, 0 to 230 to 230The hour of the daily counts snapshot that feeds the trend lines. It runs at 15 minutes past, in the appliance time zone (Settings → General → Company), so the default is 00:15. A missed day is caught up on the next run
Show trends on the Overviewswitchon or offonControls the small trend lines on the key figures. Switching it off only hides them: snapshots keep being recorded, so the history is there when you switch it on again
  • Trend lines need at least three days of snapshots (the Changes per day line needs three complete days before today). Before that there is no line and no placeholder. The first snapshot after an upgrade is written once the services have been up for half an hour and the existing software lists are processed, so the lines do not start from the half-finished state.
  • Trend lines are fleet-wide, so they are not shown to users whose role or account is limited to tags. They see a note that trends are available to unrestricted users.
  • Snapshots are kept for three years. That period is fixed.

04 Software catalog defaults #

Hidden by default is a list of software categories (Browser, Security, Endpoint protection, Remote access, Database, Web server, Runtime, Development, Productivity, Monitoring, Backup, Virtualization, Networking, Driver, OS component, Update, Other). Products in a ticked category are left out of the Software catalog, the Overview’s software panels and the flyout’s top list, unless someone switches the hiding off or names the category in the filter.

  • The default ticks Update, Driver, OS component and Runtime. The label of the switch on the Software page follows this list.
  • Hiding Endpoint protection only hides the products from the lists; the endpoint-protection coverage on the Overview does not change.
  • Hidden products stay stored, keep generating change history and are still counted in the footnote under the catalog.
  • Unticking everything lists every category; the catalog switch is then disabled with the tooltip No category is hidden by default.

05 Saving, limits and the audit log #

Save changes
Active once something changed and every field is valid. The page tells you what now applies in words, for example that servers are fresh within 48 h.
Discard
Puts the form back to the saved values.
Restore defaults
Fills the form with the factory values. Nothing changes until you save.
Out-of-range numbers
The form shows the limits and refuses what it can. A number the server still has to adjust (for example a fresh target above the stale limit) is saved at the adjusted value and the message lists which one, including a value that was reduced although you did not change it (for example the server target, when you lower the stale limit).
How fast it takes effect
Freshness and the hidden categories apply to the Overview, the Assets freshness filters and the Software catalog at once on the server that saved. Another API worker may show the old summary for up to a minute. The retention and the snapshot hour are read by the background tasks on their next pass.
Audit
Every change is recorded in the audit log (action inventory.settings.update) with the old and new value of each changed setting. Saving without a change writes nothing. If the audit entry cannot be stored the save is refused and nothing changes; try again, and contact an administrator if it persists.
Shortening the retention is permanent

Reducing Keep change history for removes the older changes at the next daily clean-up and they cannot be restored. If you keep change history for audit evidence, check your audit period before lowering the number.

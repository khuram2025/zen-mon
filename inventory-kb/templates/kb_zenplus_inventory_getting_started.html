ZenPlus Inventory

Getting started: what feeds Inventory

Inventory has nothing to install or configure. It is built from what ZenPlus already collects. This article explains which collector supplies which fact, how often each one reports, why servers and network devices age at different speeds, and what is not collected.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Administrators Reading time ~7 min

  1. What feeds Inventory
  2. What you need to do
  3. How fresh the data is, and why

01 What feeds Inventory #

Inventory does not poll or scan anything itself. It reads facts the existing collectors already store, and normalises them into one identity per machine.

SourceFeedsReportsCounts as fresh for
Windows agent (servers) Operating system name, version and build; CPU model and core count; installed memory; physical disks; the list of installed software The inventory (operating system, hardware and software list) is collected by default every 6 hours. The interval is a setting of the agent on each server (collectors.inventory.interval_seconds in %ProgramData%\ZenPlus\Agent\config\agent.yaml); it is not a field of Agent Policies. The agent also runs one collection when it starts 24 hours by default
SNMP polling (network devices) Vendor, model, serial number, operating system or firmware version, the device’s own description text, and chassis and module details (ENTITY-MIB) On every successful SNMP poll of the device 2 hours by default
Vendor monitoring templates (FortiGate, Palo Alto, F5) The exact firmware version, and for F5 the serial number, where the plain SNMP system group does not carry it With the device’s regular poll A template value older than 24 hours is only used when nothing fresher exists, and is marked Template (old)
Discovery Registers servers and network devices so the collectors above have something to report on When you run or schedule discovery Not applicable

The freshness targets in the last column are the defaults. An administrator can change them under Inventory Settings; see Inventory settings.

One machine is one asset

A Windows server that is also polled over SNMP exists twice in ZenPlus: as a server (from the agent) and as a network device (from SNMP). When the server is linked to its SNMP device, Inventory counts the machine once, as the server, and uses the SNMP side to fill gaps, for example a serial number the agent does not report. The Sources column of the Assets list shows both sources.

Inventory never guesses the link from an IP address. The link exists when the server was created or matched by a discovery import that also holds its SNMP device, or when it was set through the API (device_id of the server). Enrolling an agent does not create it, and the Servers page has no control for it. A machine that was added as an agent server and, separately, as a device therefore appears twice in Inventory, once as a server and once as a device; search for its address on the Assets list to see both rows. See why the counts differ from other pages.

02 What you need to do #

Put the Windows agent on your servers

The agent is what reports the operating system, hardware and installed software of a server. Servers appear in Inventory as soon as they exist in ZenPlus, but without the agent they have no software list and may have no operating-system version. The installed agents are listed under Servers → Agent Fleet.

Make sure your network devices answer SNMP

A device that is added but does not answer SNMP has no model, serial or firmware, and shows as Never or Stale. Add devices through Discovery and confirm the SNMP credential works; the device’s own page shows the last poll.

Give it a few minutes

A background task normalises raw values every two minutes. A server’s own upload is normalised straight away, so an agent server appears within seconds of its report. The Overview refreshes itself every minute; the line under the tabs shows when the figures were computed.

Open the Overview and read the health panel

It lists what is still missing. See Reading the health panel and freshness badges.

If the Overview shows Nothing in the inventory yet with three cards, no server or device exists yet: the cards link to the Agent Fleet and to Discovery (each only if your role may open it).

03 How fresh the data is, and why #

Each asset has a last inventory time: the last time one of the sources above successfully reported its identity. That is a different thing from last seen, which only says the machine answered a ping or a heartbeat. A server can be up and answering while its agent has stopped sending inventory, and Inventory tells the two apart.

BadgeServer (default)Network device (default)
FreshReported within 24 hoursReported within 2 hours
AgingOlder than 24 hours, up to 7 daysOlder than 2 hours, up to 7 days
StaleOlder than 7 daysOlder than 7 days
NeverAn agent server that has not delivered an inventory reportA device polled over SNMP that has not completed a poll since Inventory was installed
Not reported by designA server whose collection mode has no inventory upload (SSH, WMI, WinRM, SNMP-only or none) and that never reportedA ping-only device, or a child device managed through a controller

Not reported by design is not a gap. The asset stays in the Assets list and is counted (freshness=not_applicable, its own line on the line under the tabs and in the health panel), but it is not counted as Never, it is left out of the fresh percentage, and the checks for a missing OS version, model, serial number or vendor skip it, because it has nothing to report. Only a server with the ZenPlus agent can send an inventory in this release, so a server that is monitored over SSH, WMI, WinRM or SNMP only will never become Fresh: install the agent if you want its operating system, hardware and software here. A server that has ever delivered a report keeps a normal badge.

Servers get a longer target than devices because the software list is large and the agent sends it every six hours by default, while a device is re-read on every poll. The time of the oldest figures on a page is also limited by caching: the summary behind the Overview is computed at most once a minute, and the operating-system and hardware pages refresh every five minutes. The line under the tabs always shows the time the figures were computed.

If you lengthen the agent’s inventory interval, change the target too

If you set the inventory interval of the agents (collectors.inventory.interval_seconds in the agent configuration file) higher than the server freshness target (24 hours by default), servers will show Aging between reports even though nothing is wrong. Raise the server target in Inventory Settings to match.

04 What the first days look like #

  • For the first minutes the screens say they are still working. Raw names and versions that were stored before Inventory existed are normalised in the background, in steps of 100,000 software rows about every two minutes, so roughly two minutes for every 100,000 rows (the first step about 45 seconds after the services start). Until that is done every Inventory page shows Normalising existing software lists; figures are incomplete, the software catalog is partial, and the endpoint-protection line counts servers whose list has not been processed as unknown, not as missing. An estate of 500 servers with 400 titles each (200,000 rows) is complete in about three minutes; 2,500 servers about 20 minutes; 5,000 servers about 40 minutes. The page refreshes its figures when processing finishes; read no figure as a finding while the banner is shown.
  • Network devices read Never until their next SNMP poll; servers that already had a software list keep their real age. A server that held a software list when the release was installed is given the time of its last list as its last inventory, so it reads Fresh, Aging or Stale as it truly is. A server that never delivered a list reads Never (agent) or Not reported by design (other collection modes) until it reports, up to 6 hours with the default agent interval. The Fresh inventory figure climbs as they report. Nothing is wrong.
  • The first report of a server records nothing as a change. It becomes the baseline; only differences from the next report on are history. Servers that already held a software list when the release was installed were baselined at that moment.
  • History starts at installation and cannot be reconstructed. ZenPlus never invents events from the past. The Changes page prints the day change capture began, and that is the day to quote even if the first recorded change came later. See When history starts.
  • Trend lines appear after the third daily snapshot. The key figures Assets, Software titles and Fresh inventory show a small trend line once at least three daily snapshots exist; Changes per day needs three complete days before today, so it appears one day later. Until then there is no line and no placeholder. The first snapshot is written only after the services have been up for half an hour and the normalising backlog is empty, so the lines do not begin with the half-finished state of the upgrade.
  • A few changes may appear on the first software report after the upgrade. A server whose list names the same program twice (for example a 32-bit and a 64-bit entry with different versions) used to keep the last one listed; Inventory keeps the highest, so each such program records one version change on that first report.
  • “First seen” of software that was already installed reads “before date”. The date is the day Inventory began recording (the day change capture began), not the day the program was installed; point at it to see the earliest date known, which is the install date the machine reported when it reported one. Software that appears after that day shows the day it was first seen.

05 What is not collected #

Not collectedConsequence today
Installed software on Linux servers and on servers monitored without the Windows agentTheir software list is empty, and a server with no software report counts as unknown in the endpoint-protection coverage rather than as missing. Servers that stopped reporting keep the last list they sent, and it stays in the software figures until the server is removed or reports again
Server manufacturer, model, serial number, BIOS and physical-or-virtualThe Windows agent in this release does not report them. Those fields are blank for servers, and the health checks for missing model, serial and vendor apply to network devices only, so servers are not counted as gaps
Installed Windows updates (KB numbers)Not shown. Update entries that a software list contains are filed under the hidden update category
Software beyond the first 1,000 titles of a serverThe agent sends at most 1,000 titles, sorted by name, and drops the tail. The server is flagged Software list truncated

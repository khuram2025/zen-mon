ZenPlus Inventory

Software and versions

Every product installed on your servers as one row, with how many servers have it and how its versions are spread. Open a product to see its versions, the servers it is installed on, its history and the raw names that were grouped into it.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators Reading time ~9 min

01 The catalog #

Inventory & Compliance → Software lists one row per product. Software comes from the Windows agent’s list of installed programs, so the catalog covers servers that report through the agent. A server that stopped reporting keeps the last list it sent, and that list stays in the host and install counts until the server is removed or reports again (the line under the tabs shows how many assets are stale or never reported).

Right after an upgrade the catalog fills in step by step while existing lists are processed. Until it is done the page says Normalising existing software lists; figures are incomplete, and an empty catalog with that message means the lists are not processed yet, not that nothing is installed.

ColumnMeaning
Product, Publisher, CategoryAs normalised. Click the product name for its page
HostsDistinct servers that have the product. A link: it opens the Assets list of exactly those servers, and the list total equals the number
InstallsSoftware entries. A server that lists the product twice (a 32-bit and a 64-bit copy, or a per-user copy) counts once as a host and twice as installs
VersionsNumber of distinct versions, with a stacked bar of hosts per version, newest on the left. Two spellings of one version (7.2 and 7.2.0) are one version
LatestThe newest version seen on your own servers
First seenThe earliest first-seen date among the product’s installations that are stored now: when Inventory first saw it on a server whose entry still exists (a server that was deleted no longer counts). A product that was already installed when Inventory began recording reads before and the date recording began (point at it for the earliest date known). The CSV export of this table carries the stored date without that word: see CSV export
  • Search needs every word you type to appear in the product name or the publisher (visual c++, microsoft). Category can be chosen several at a time; Publisher shows how many products each choice would give.
  • Filters, sort and page are in the address bar, so a view can be bookmarked and shared.
  • The default sort (most hosts first) is the quickest. Sorting by version count or latest version has to read every product and can take a second or more on a very large estate.
  • With the inventory.export permission, Export downloads the filtered catalog. See CSV export.

02 How raw names become products #

A raw program name rarely says what the product is: it may carry a version, a language, an architecture or a build number. Inventory groups titles with rule packs that ship with ZenPlus, so that the many names of one product count as one:

Raw name reported by the serverProduct in the catalog
Microsoft Visual C++ 2015-2022 Redistributable (x64) - 14.38.33135Microsoft Visual C++ 2015-2022 Redistributable (category Runtime); the 2005, 2008, 2010, 2012 and 2013 redistributables are separate products, because they are installed side by side on purpose
Java 8 Update 391 (64-bit)Java SE Runtime (category Runtime)
Google ChromeGoogle Chrome (category Browser)

Each product carries a normalisation status, shown as a pill on the product page:

StatusMeaning
NormalizedA catalog rule placed the product
Publisher onlyNo product rule matched, but the publisher is recognised
UnmatchedNeither the product nor the publisher is recognised. It is grouped under a name derived from its title and is still counted

Under the table, N titles unmatched is a link to the unmatched products. Editing catalog rules is not part of this release; the product page’s Evidence tab shows the raw names behind a product so a wrong grouping can be reported to Zentryc support.

03 Hidden categories #

Windows updates, drivers, operating-system components and runtimes make a software list long without telling you much about the applications you run. By default these four categories (Update, Driver, OS component and Runtime) are left out of the catalog, the Overview and the flyout’s top list.

  • The switch above the table is on by default and its label is built from the categories hidden by default, so with the shipped settings it reads Hide updates, drivers, OS components and runtimes. An administrator chooses the categories in Inventory settings and the label follows; with more than four it counts them (Hide 5 categories hidden by default) and the tooltip lists them. A list that an administrator has saved is used exactly as saved: if it does not contain Runtime, runtimes such as Java or the Visual C++ redistributables are listed.
  • A note under the table says how many products and installations are hidden, with a Show all N link that includes them and Hide them again to go back.
  • Choosing a category in the Category filter always lists it, hidden or not.
  • Hidden software is still stored and counted; nothing is deleted.

04 The product page #

Click a product name. The page has a header with the product’s status pill, publisher, category and product key (the key is the last part of the address and the value of the product filter), four figures, and four tabs. The tab is kept in the address (?tab=).

Figures
Hosts (a link to those servers), Versions, Latest seen (a link to the servers on it) and Behind latest, the number of hosts without the newest version. Behind latest is plain text: a host that runs two versions counts once, and the filters cannot say “not this version”.
Versions
A bar per version with its host count and a generation pill (N, N-1, Older). Click a version to open the servers that run exactly that version. Installations with no version reported are listed as No version reported.
Installed on
The servers with the product: server, package name, version, architecture, source (the registry area the entry was read from: HKLM, HKCU (current user) or, for 32-bit programs on 64-bit Windows, HKLM (32-bit)), install date, first seen and last report. Searchable and sortable; a server opens in the asset flyout. With inventory.export, the same rows download as CSV.
Timeline
Installs, removals and version changes of this product over 7, 30 or 90 days, newest first, grouped by day, as on the Changes page.
Evidence
The raw package names and publishers that were grouped into this product, how many hosts and installations report each, and how the normaliser reads each one today. Read-only.

05 Versions, N and N-1 #

Versions are ordered with the product’s own version rules, not as text, so 9.2 is older than 10.1. The newest version seen on your servers is N, the one before it is N-1, and everything earlier is Older: two or more versions behind the newest seen. This is a view of your own estate; it does not know the vendor’s latest release.

  • Two spellings of one version (1.0 and 1.0.0) share a generation.
  • A version the rules cannot parse (for example nightly-build) is shown as Unordered and follows the ordered ones. ZenPlus does not guess where it belongs.
  • A product that has packages from more than one system, for example a Windows installer and a Linux package, is ranked in one group per system, because their version numbers cannot be compared. The page says Versions that follow different numbering schemes are ranked apart: one scheme’s version is never compared with another’s, so each group has its own N.
  • A missing version is not a version. It is reported separately and never counted as the oldest.

06 Upgrades that look like an install and a removal #

Some products put their version in their name (Java 8 Update 391, the Visual C++ redistributables). When one is upgraded, the old title disappears and a new title appears: the agent’s list shows one removal and one installation. Inventory recognises the pair, when both happened on the same server at the same moment, and shows it as one upgrade in the Timeline and on the Changes page, with the count of such pairs noted beside the statistics. See Changes.

07 What the catalog cannot see #

  • Servers without a software report (no agent, Linux, a new agent that has not run its first inventory) have no software in the catalog. Linux software is not collected in this release.
  • Servers that stopped reporting are still in the figures with the last list they sent; nothing in this release excludes them by age.
  • Titles beyond the 1,000th of a server. The agent sorts its list by name and cuts it at 1,000. The server is flagged Software list truncated (see health), and the titles beyond the cap are not counted anywhere.
  • Programs that do not register themselves as installed (portable applications, files copied into a folder) are invisible to the Windows list of installed programs.

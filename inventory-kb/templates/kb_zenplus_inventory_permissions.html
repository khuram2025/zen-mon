ZenPlus Inventory

Permissions, tag scope and team roles

Three permissions control Inventory, tag scope narrows what each person sees, and the built-in roles come with sensible defaults. Custom roles do not get Inventory access automatically. This article explains who can see, export and change what.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Administrators Reading time ~7 min

01 The three permissions #

PermissionGrantsRisk level
inventory.viewEvery Inventory page and the data behind it, within the person’s tag scope. The Inventory group appears in the sidebar only with this permissionStandard
inventory.exportThe Export buttons: CSV downloads of assets, software, installations, operating systems, hardware and changes. See CSV exportSensitive: serial numbers and software lists are reconnaissance data
inventory.manageChanging the settings on the Inventory Settings page: freshness targets, history retention, snapshot time, trends switch and hidden categories. Anyone with inventory.view can open the page and read the valuesStandard
  • In the role editor (Settings → Users & Access → Roles & Permissions), ticking Export or Manage also adds View (“Also adds: inventory.view”). The server checks each permission separately at the time of a request: a role that somehow holds only inventory.export can download but cannot browse the pages.
  • A person without inventory.view does not see the Inventory group in the sidebar. Opening an Inventory address directly shows an explanation that names the missing permission and says to ask an administrator, not a blank page.
  • inventory.view shows what is installed on servers, including software that the separate servers.view permission also protects on the server pages. Inventory deliberately makes that visible to anyone you give it to, within their tag scope. Grant it with that in mind.

02 Built-in roles #

When ZenPlus is upgraded to this release, the built-in roles are brought to their new definition once (built-in role definition version 6). Each change is written to the role history, showing exactly which permissions were added.

RoleViewExportManage
AdminYesYesYes
OperatorYesYesYes
ViewerYesNoNo
Read OnlyYesNoNo
Network TeamYesNoNo
Systems TeamYesNoNo
Security TeamYesNoNo
Application TeamNoNoNo

The reasoning: inventory of devices and servers is core to the network, systems and security teams’ work, and CIS controls 1 and 2 are a security-team concern, so those three can look. The Application Team sees applications, not the estate, so it gets nothing. No team role can export or change settings; those stay with operators and administrators. If a built-in team role does not suit you, create a custom copy and tick what you need.

The one-line descriptions of the team roles may not mention Inventory

The upgrade brings the permissions of the built-in roles to the new definition; it does not rewrite their one-line descriptions. On an appliance that already had the team roles, the descriptions of Network Team, Systems Team and Security Team in the role list therefore still do not mention Inventory. (A new installation shows them ending Includes read access to Inventory (inventory.view).) The permission matrix of the role is the source of truth.

03 Custom roles #

An upgrade never changes a custom role, on purpose: a new permission must never be granted to a role that an administrator wrote by hand. So after the upgrade:

List the custom roles whose members should see Inventory

Typical candidates: roles copied from Operator or Viewer, and roles for auditors and security staff.

Grant inventory.view in the role editor

In the Access step, set the Inventory module to View. Choose Full only for administrators of the module: it adds inventory.manage. inventory.export is listed separately as a sensitive permission and is ticked on its own, only for those who must download CSV files. The Review step previews the menu the role will see.

Check the tag scope

If the role has a visibility scope, Inventory follows it. Confirm the tags match the assets the team should see (next section).

04 Tag scope #

A person’s visibility scope is the tags set on their own account plus the tags set on their role (the Visibility step of the role editor). A person with no scope sees everything; a person with a scope sees only assets that carry at least one of the tags, compared without regard to case. Administrators (system.admin) are never scoped.

Inventory applies the scope to everything, so a scoped person does not see the rest of the estate even in a total:

WhereWhat a scoped person gets
Every figure, chart and listCounts over the visible assets only. A badge under the tabs says Showing assets tagged …
Assets without tagsInvisible to a scoped person. Tag the assets that a team should see
The asset flyout of an asset outside the scopeAsset not found, exactly as for a deleted asset
SoftwareHosts, installs, versions and the publisher list are those of the visible servers; a product that none of them has is absent
ChangesOnly changes of visible assets. Changes of an asset that has since been deleted are not shown, because its tags are gone
Trend linesNot shown. They are fleet-wide and carry no tags, so a scoped person sees a note that trends are available to unrestricted users
CSV exportsThe same rows the list shows that person
Inventory settingsNot tag-scoped: settings are appliance-wide

A scope that matches no asset is not an error: every list is empty and every count is zero, and the page says Your role limits Inventory to assets tagged …, and none carry those tags yet.

05 Links to other pages #

Seeing a machine in Inventory does not open its own page. Links from the asset flyout to Open server page and Open device page appear only if the person also holds servers.view or devices.view; otherwise the entry is shown locked with the permission named. The Overview’s first-run cards to the Agent Fleet and to Discovery follow the same rule (servers.view and discovery.view).

06 What is audited #

  • Every CSV export is written to the audit log before the first byte is sent: who, which dataset, the filters used, how many rows and whether the file was cut at the row cap.
  • Every change to Inventory settings is written with the old and new value of each setting that changed.
  • If the audit entry cannot be stored, an export is refused before any byte is sent and a settings save is refused and changes nothing: the request answers with an error that says the audit log is unavailable. Try again, and contact an administrator if it persists.
  • A refused or invalid request writes nothing.

Browsing is not audited.

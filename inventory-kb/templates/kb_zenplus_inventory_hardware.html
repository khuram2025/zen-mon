ZenPlus Inventory

Hardware

Which network vendors and models you run, how complete their serial numbers are, which firmware each model is on, what chassis and modules the devices contain, and what your servers are built from. This article explains each panel and what is, and is not, reported for servers.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators Reading time ~6 min

On this page

  1. Network hardware
  2. Serial coverage
  3. Models by firmware
  4. Modules and components
  5. Server hardware

01 Network hardware #

Inventory & Compliance → Hardware opens with a summary line (the number of network devices and vendors, the number of known models and how many devices have no model, and the number of servers) and the Network hardware table: one row per vendor, and under it one row per model. A model count always means known models; a device with no model is not a model, so the line reads, for example, 12 models plus 3 devices with no model.

ColumnMeaning
Vendor / modelThe vendor, then its models. A vendor row counts every device of that vendor; its model rows add up to it
DevicesA link to the Assets list of exactly those devices, whose total equals the number
Firmware versionsHow many different firmware versions those devices run
Serial coverageThe share of the devices that can report that report a serial number. See below
ModulesNumber of module components read from the devices’ ENTITY-MIB. Text, not a link: components are not machines

A device with no known vendor is a row called Unknown vendor, and a vendor with devices whose model could not be read has an Unknown model row. Both are counted and open lists (vendor=unknown and model=unknown in the address). A device that cannot report by design (ping-only, or managed through a controller) stays in its row; the row says N not reported by design with a link, and those devices are left out of the serial coverage. A vendor row with a known vendor has a Firmware matrix action that shows its models in the matrix (see below).

02 Serial coverage #

Serial numbers matter for support contracts, RMA and audit, so each vendor and model shows the share of its devices that can report one, as a percentage in a pill (green at 100%, amber from 80%, red below). The pill’s tooltip and screen readers add the words, so the colour is never the only signal:

CoverageWords shown
100%All serials known
80% to under 100%Some serials missing
Under 80%Many serials missing

Next to the percentage, N missing is a link to the devices without a serial number (the same list as the missing serial health check, with the row’s own filters).

The percentage never hides a missing serial number

The percentage is rounded to one decimal place, but it only reads 100.0% (and the pill All serials known) when every device that can report a serial number has one. A group with even one missing serial reads at most 99.9%. The N missing link beside it always shows the exact number and opens the list.

Some platforms never publish a serial number over SNMP

A device that does not expose the standard chassis table (ENTITY-MIB) cannot report a serial number to ZenPlus. A low coverage for one vendor usually points at the SNMP view or at that platform, not at ZenPlus. See why a device is Unknown.

03 Models by firmware #

The matrix answers “is every device of this model on the same firmware?”. Pick a vendor (the choice is kept in the address as ?vendor=). Rows are models, columns are firmware releases, newest first with Unknown last, and each cell is the number of devices of that model on that release.

  • Every cell shows its number; the shade of the cell only reinforces it, so the matrix never depends on colour. A legend gives the shade steps.
  • Each non-empty cell is a link to the devices of that model on that release.
  • The summary above the matrix says, for example, Cisco: 12 models, 4 of them on more than one release. A model on more than one release is the one to look at first.

04 Modules and components #

Devices that answer ENTITY-MIB publish the parts they are made of. Inventory groups them by class and model. The classes are Chassis, Backplane, Module, Power supply, Fan, CPU and Stack.

  • The link on a group counts the devices that have it and opens that device list. The number of components (and how many report a serial number) is plain text: a device can hold several, so components can outnumber devices — two power supplies in one switch are two components in one device.
  • The serial numbers of a device’s components are in that device’s flyout, under Modules, which is the list you want for RMA planning.
  • A group whose model is not reported shows as model unknown and is still counted.

05 Server hardware #

For servers, the Windows agent reports the CPU, the installed memory and the physical disks. The Server hardware panel shows the distributions, and every row links to the servers behind it:

DistributionGroups
CPU modelsThe 25 most common models; a note says how many more models on how many servers are not listed
Installed memoryUp to 8 GB, 9 to 16, 17 to 32, 33 to 64, 65 to 128, over 128 GB (binary gigabytes)
Physical disks1 disk, 2, 3 to 4, 5 to 8, 9 or more
VirtualizationPhysical or virtual, when reported
Manufacturer, model, serial number and BIOS of servers are not reported

A server’s manufacturer, model, serial number, BIOS version and whether it is physical or virtual are not reported by the Windows agent in this release. The Virtualization section says so instead of showing an empty chart, and servers do not count toward the missing-model, missing-serial and unknown-vendor health checks. A server that is also polled over SNMP takes its vendor, model and serial number from that device.

Servers that have not reported their hardware yet appear under Unknown in every distribution, and the panel says so when no server has reported at all. Unknown is a row, not a gap.

ZenPlus Inventory

CSV export

Download what you are looking at as a spreadsheet-ready file. This article lists where the Export buttons are, exactly what a file contains and leaves out, how it is protected against spreadsheet formula injection, and what is logged.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators and auditors Reading time ~6 min

01 Where to export #

An Export button (a download icon) appears on a page only for people with the inventory.export permission. It is not on the Overview.

PageExports
AssetsThe assets list with the active filters and sort
SoftwareThe product catalog with the active filters and sort
Product page, Installed on tabThe installations of that product (one row per server entry), with the version filter and search
Operating SystemsOne row per version, for the All, Servers or Network choice
HardwareThe vendor, model, module and server-hardware tables
ChangesThe change events in the window, with the filters

A toast confirms the start: Export started, with the number of rows. If the file was cut at the row limit it reads Export started, cut at the row limit.

02 What a file contains #

  • The whole result, not the page. The file holds every row that matches your filters, not just the 50 on screen, in the same order as the list.
  • Exactly what the list shows you. The export is produced by the same code as the list, with your tag scope. A person limited to tags exports only the assets they can see.
  • One consistent moment. The assets, installations, operating-system, hardware and change files are read in a single consistent view of the database, so they never mix the state before and after a change that happened while the file was being written. The software file is built from the same product table that the Software page shows: its rows and their order are consistent, but each figure in it (hosts, versions, latest version) is a value that page showed within the minutes around the export, not one instant.
  • Unknown is kept. Assets with an unknown OS, vendor or model are rows like any other, with empty cells.

The file is named zenplus-inventory-<dataset>-<YYYYMMDD>.csv with the date in UTC, for example zenplus-inventory-assets-20261009.csv.

Useful conventions: key and asset_key are the asset address (server:<id> or device:<id>) that also appears in the ?asset= of the Assets page; tags and sources are written a;b;c; timestamps are UTC; marker is true for the daily Change budget exceeded row and snapshot_truncated for changes recorded while a software list was capped (see Changes).

04 First-seen dates in the files #

The first_seen column of the software dataset and the first_seen_at column of the installations dataset are written as stored, in UTC, with no before marker. The screens print a first-seen date at or before the day Inventory began recording as before <that day>, because for software that was already installed it is not the day Inventory saw it:

  • When Inventory was installed, every software entry that already existed was stamped with the time of the upgrade, and where the machine had reported a plausible install date the stamp was replaced by that install date (for example 2024-08-04T17:15:03Z). Both are dates on or before the capture start, and neither is when Inventory first saw the product.
  • A value after the capture start is the day the product first appeared on that server.
  • The capture start is printed in the footnote of the Changes page. Compare the column with it before you use it as an observation date, for example in an audit.

05 File format and safety #

Encoding
UTF-8 with a byte-order mark, so Excel opens accented and non-Latin names correctly. Lines end with CRLF and there is one header row.
Values
Numbers are written as numbers, booleans as true and false, lists as a;b;c. A cell containing a quote, comma or line break is quoted.
Formula injection guard
A spreadsheet runs a cell that starts with =, +, - or @ (or a tab or carriage return) as a formula. A hostile software title or hostname can be written that way, so such text cells get a leading apostrophe and stay text. If you see a leading ' in a name, that is the guard, not part of the name.
Not cached
The download is marked no-store, so a proxy does not keep a copy.

06 Row limit #

A file holds at most 200,000 rows. If your filters select more, the file holds the first 200,000 in the list’s order (newest first for changes) and the toast says Only the first N of M rows are in the file. Narrow the filters to export the rest. The audit entry records that the file was cut. Exports of tens of thousands of rows finish in a few seconds.

Few at a time. An export keeps a database connection and a consistent view open while it streams, so each person is limited to one export at a time and the appliance to two at once. Both limits are counted separately in each of the appliance’s two API processes, so in practice a person can sometimes have two running and the appliance four. A request over a limit is refused at once with the message you already have an export running; wait for it to finish or too many exports are running; try again shortly (with a retry hint of 10 seconds); start it again when the other one has finished. A download that the browser stops reading for two minutes is abandoned and its connection is released.

07 What is not included #

  • The flyout’s detail: per-component serial numbers of a device’s modules and the full software list of one server are not in the assets file. Use the product pages’ Installed on export for who has a product, and the flyout for one machine.
  • Raw evidence (the unprocessed text a device or agent reported) and the source age of each identity value.
  • Credentials of any kind: no Inventory dataset contains an SNMP community, password or key.
  • Anything outside your tag scope.

08 Permissions and audit #

Serial numbers, software lists and version numbers are what an attacker looks for first, so inventory.export is classed as sensitive and is granted separately from viewing: a Viewer can browse everything and download nothing. Among the built-in roles only Operator and Admin can export. See Permissions.

Each export is written to the audit log before the first byte is sent, with the person, the dataset, the non-empty filters applied (and the effective sort), the number of rows and whether the file was cut at the limit. The record exists whether or not the browser finishes the download. If the audit entry cannot be stored, the export is refused before any data is sent, with a message that the audit log is unavailable; try again, and contact an administrator if it persists.

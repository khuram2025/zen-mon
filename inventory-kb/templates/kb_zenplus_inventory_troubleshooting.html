01 Why is a device Unknown? #

For a network device, Inventory shows what the SNMP poller read. An empty or Unknown operating system, model, serial number or vendor means one of these. Open the device in the asset flyout first: the source badge and age of each value and the Raw evidence list narrow it down in seconds.

What you seeCauseWhat to do
Freshness Never, every field blankThe device has not completed an SNMP poll since Inventory was installed (new device, wrong SNMP credential, ACL, or it is down)Check the device’s own page for its last poll and fix the SNMP credential or reachability
Vendor Unknown, other fields filledThe device’s vendor identifier (sysObjectID) is not matched by any device profileNote the sysObjectID in the flyout’s Device section and send it to Zentryc support so a profile can be added
OS or firmware Unknown, vendor knownThe description text (sysDescr) of the device does not carry a version, and no vendor template supplies oneLook at Raw evidence. For FortiGate, Palo Alto and F5 the version comes from a monitoring template; make sure the device is polled with its template
Model and serial missing, vendor and OS knownThe device does not answer ENTITY-MIB, so no chassis can be readMake sure the SNMP view includes ENTITY-MIB; test it below
Values present but badge says Template (old)The vendor template was not read in the last 24 hours, so an older value is being usedThe device’s template group is not being polled, or the device was unreachable; fix polling and the badge returns to Template
The flyout says the device is managed by a controllerIts inventory comes from the controller, not from SNMPCheck the controller integration

Prove it with two commands

Run these from any Linux host with the credential ZenPlus uses. The first returns the description text and vendor identifier; the second returns the chassis model and serial number if the device publishes ENTITY-MIB:

# sysDescr and sysObjectID
snmpget -v2c -c <community> <device-ip> 1.3.6.1.2.1.1.1.0 1.3.6.1.2.1.1.2.0

# entPhysicalSerialNum (.11) and entPhysicalModelName (.13)
snmpwalk -v2c -c <community> <device-ip> 1.3.6.1.2.1.47.1.1.1.1.11
snmpwalk -v2c -c <community> <device-ip> 1.3.6.1.2.1.47.1.1.1.1.13

If the second returns nothing, the device (or its SNMP view) does not publish ENTITY-MIB and ZenPlus cannot learn a model or serial number from it. That is a property of the device, not a fault in Inventory. For SNMPv3, use -v3 with your user and keys instead of -v2c -c.

02 Why is a server’s operating system Unknown? #

  1. The server has never reported. Freshness is Never. Servers report their operating system through the Windows agent; check Servers → Agent Fleet for the server and its last report.
  2. The server was registered without the agent (for example by discovery). It is counted, and its operating system is whatever the discovery scan recorded, which can be blank or coarse. The agent’s own report replaces it once the agent is installed.
  3. The agent reported text the rules do not recognise. The flyout’s Raw evidence shows the name and version the agent sent. Send it to Zentryc support if it is an operating system that should be recognised.

Unknown is a value on purpose: click the Unknown row on the Operating Systems page to list exactly these machines.

03 Why does a server show no software? #

Installed software reaches Inventory from one place only: the Windows agent’s list of installed programs. A server therefore has no software when:

SituationWhat Inventory shows
No agent is installed (agentless monitoring)No software list. Install the agent
It is a Linux serverNo software list: the agent in this release collects software on Windows only
The agent was installed recently and has not run its first inventory collectionThe flyout says No software report has been accepted yet. The first collection runs when the agent starts and then every 6 hours by default
The inventory collector of the agent is switched offCheck collectors.inventory.enabled in the agent’s own configuration file (%ProgramData%\ZenPlus\Agent\config\agent.yaml). A policy can also switch it off through its feature_flags (inventory or collect_inventory set to false), which are set through the API; the Agent Policies page has no switch or interval for the inventory
The title is in a hidden categoryThe flyout and catalog leave out Update, Driver, OS-component and Runtime software by default. The flyout counts them as hidden; the catalog note under the table shows how to list them
The title sorts after the 1,000thThe agent cut its list; the server is flagged Software list truncated
The program is portable and never registered itself as installedNot visible to the Windows list of installed programs

A server that has never delivered a software list is neither “covered” nor “without” in the endpoint-protection figure: its state is unknown, because nothing can be said about it. A server that reports no services at all is unknown as well, because built-in Defender shows only as a running service.

04 Why are the counts different from the Servers page? #

Inventory and the other pages answer slightly different questions. Compare like with like:

DifferenceExplanation
Servers and network devicesInventory’s Assets total includes both. The Servers page lists servers only; the Devices page lists network devices. Use the Kind filter to compare
One machine, one asset — only when linkedA server that is also polled over SNMP exists as a server and as a network device. When the server is linked to that device, Inventory counts it once, as the server; the Devices page also lists the SNMP side. The link is made by a discovery import or through the API, never from an IP address and not by enrolling an agent. A machine that was added as an agent server and separately as a device, with no link, is two assets (one of kind server, one of kind device); search for its address on the Assets list to see both
No status filterInventory lists every server and device that exists, including ones that are down or not reporting; those show as Stale or Never. A page that defaults to a status or site filter shows fewer. Clear its filters before comparing
Your tag scopeIf your role or account is limited to tags, Inventory counts only those assets (a badge under the tabs says so). A colleague without a scope sees larger numbers
The Devices page counts a device’s own valuesThe Vendor and Model menus of the Devices page count what each device itself reported, as the poller stored it, and its OS version menu counts the normalised version where Inventory has one. Inventory counts the normalised vendor, in which spellings and aliases are merged (Cisco and Cisco Systems are one), so a vendor can show different counts on the two pages. Neither is wrong, and the list behind each number has exactly that many rows
Software: products, not titlesInventory groups many raw titles into one product, so the number of products is lower than the number of raw titles. Hosts counts servers; Installs counts entries. A server’s own software tab lists every raw entry
Hidden categoriesUpdate, Driver, OS-component and Runtime software is left out of the catalog and Overview by default. Switch the hiding off to compare totals
Servers that stopped reportingA server that stopped reporting keeps the last software list it sent, and that list stays in the host, install and version figures until the server is removed or reports again. The line under the tabs counts how many assets are stale or never reported
TimingThe Overview summary is computed at most once a minute, and the OS and hardware pages every five minutes. The time is in the line under the tabs

Inside Inventory the numbers always agree with each other: click any number and the list that opens has exactly that total. If that is ever not so, please tell Zentryc support, because it is a defect.

05 Everything says Never after the upgrade #

This is expected for a short while, and it is not the same for every asset:

  • A network device reads Never until its next successful SNMP poll (minutes).
  • A server that already had a software list when the release was installed shows its true age (the time of its last list), so a server that stopped reporting long ago reads Stale, not Never.
  • An agent server that never sent a list reads Never until its next inventory report (up to 6 hours with the default interval).
  • A server monitored without the ZenPlus agent, and a ping-only or controller-managed device, reads Not reported by design. It never becomes Fresh in this release and is not counted as Never. See how fresh the data is.

Fresh inventory on the Overview climbs as the rest report; nothing needs to be done. If a specific machine that can report is still Never a day later, follow section 1 or section 3.

06 The figures look incomplete right after the upgrade #

Software lists and names that were stored before Inventory existed have to be normalised once, in the background: about 100,000 software rows every two minutes, the first step about 45 seconds after the services start. Until it has finished:

  • Every Inventory page shows Normalising existing software lists; figures are incomplete, with the number of rows still to process at the last check. It disappears when the backlog is empty, and the page then refreshes its figures once. The number counts only rows that Inventory will process, so it never stays up for rows that it ignores.
  • The software catalog, the host and install counts and the version figures are partial. An empty catalog with that message means the lists are not processed yet, not that nothing is installed.
  • The endpoint-protection line counts a server whose list is not processed yet as unknown, never as without, so the gap does not flash up as a worklist of every server.
  • The Overview does not show its all-clear sentence while the message is up.

How long: roughly two minutes for every 100,000 software rows (servers × titles), plus the first 45 seconds. 200,000 rows take about 3 minutes, 1,000,000 about 20 minutes, 2,000,000 about 40 minutes. Network devices and servers without a software list are done in the first step. If the message is still there after twice that long, contact Zentryc support with the numbers shown in it.

07 A machine is up but shows Stale #

Freshness measures the last inventory, not whether the machine answers. Hover over the badge: Last seen (reachability) is recent and Last inventory (data) is old.

  • A server: the agent still sends heartbeats but its inventory collector is not running or its interval (collectors.inventory.interval_seconds in the agent’s own configuration file) was lengthened beyond the freshness target. Check that file and the agent version in the Agent Fleet.
  • A device: it answers ping but not SNMP (a changed community or user, an ACL, SNMP disabled).
  • Targets too tight: if your agents send inventory every 24 hours, a 24-hour target makes servers flicker to Aging. Raise it in Inventory settings.

08 The endpoint-protection figure looks wrong #

The figure counts servers with a complete, processed software list: covered when the list holds an antivirus, endpoint-protection or EDR product of the catalog category Endpoint protection, or when the Defender service (WinDefend or Sense) is running. Servers whose list is missing, cut at the 1,000-title cap or not yet processed, and servers that have reported no service list at all, are unknown, on a line of their own; the asset flyout names which of the four reasons applies. It shows that such a product is installed; it is not proof that it is current or working. If a server you know is protected is listed as without, check that its product is one the catalog knows (open the server in the flyout and read its software; an unknown product can be reported with its Evidence names) and that its list is complete. Details are in health and freshness.

09 Changes I expected are missing, or odd ones appear #

SymptomExplanation
Nothing before a certain dateHistory starts when Inventory was installed (the Changes page footnote names the day capture began, even if the first change came later); earlier changes cannot be reconstructed. See when history starts
A new server shows no installsIts first report is the baseline; only later differences are changes
A device’s first model or serial is not a changeA value appearing for the first time is discovery. Only a change from one known value to another is recorded
A Change budget exceeded rowThat server had reached about 2,000 software changes in 24 hours when a report arrived; the software changes of that report were not recorded. See the change budget
A removal that may not be realThe note says the list was capped at 1,000 titles; the title may have been cut off. See capped lists
A handful of “version changed” rows on the first dayA server that lists the same program twice (32-bit and 64-bit entries with different versions) used to keep the last one and now keeps the highest, so the first report after the upgrade records one change per such program
One upgrade appears as a removal and an installationProducts that carry their version in their name are stored as a new title; the list shows the pair as one upgrade when both are on the same page

10 I cannot see a page, a button or an asset #

ProblemCause and fix
The Inventory group is not in the sidebarYour role lacks inventory.view. A custom role must be granted it by hand after the upgrade. See custom roles
There is no Export buttonYou need inventory.export, which is separate from viewing
The settings are greyed out with a noteYou can read them with inventory.view; changing them needs inventory.manage
A link in the flyout is lockedThe server or device page needs servers.view or devices.view
Asset not found in the flyoutThe machine was deleted, or it is outside the assets your role covers
The lists are empty with a message about tagsYour role or account is limited to tags and no asset carries them yet. Tag the assets, or ask an administrator to adjust the scope
A colleague sees more than youTheir scope is wider or they have none. The badge under the tabs shows yours

11 There are no trend lines #

  • Too early. They need at least three daily snapshots (Changes per day needs three complete days before today, so it appears one day later). One snapshot is written each day at 15 minutes past the snapshot hour (00:15 by default, in the appliance time zone), and the first one only after the services have been up for half an hour and the normalising has finished.
  • Scoped users do not get them. Trend data is fleet-wide and carries no tags, so it is withheld from anyone limited to tags. A note says so.
  • They are switched off. Show trends on the Overview in Inventory settings. Recording continues while they are hidden.
Still stuck?

Collect the asset address from the flyout (?asset=… in the address bar), what the flyout shows under Raw evidence, the freshness badge tooltip, and the line under the tabs, then contact Zentryc support. Those four facts identify nearly every Inventory question without a further round trip.

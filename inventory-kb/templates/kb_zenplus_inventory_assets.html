ZenPlus Inventory

Assets and the asset flyout

Servers and network devices in one list, filtered and sorted on the server, with a flyout that shows what a machine is, where each fact came from and how old it is. This article covers the list, the filters, the shareable address and the flyout.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators Reading time ~8 min

01 The list #

Inventory & Compliance → Assets lists every server and every network device you are allowed to see, one row per machine. A server that is linked to its SNMP device is one row, not two; a server and a device that are not linked stay two rows (see Getting started).

The columns shown by default are Name, IP address, Vendor, Model, OS / Firmware and Last inventory. The column menu adds Kind, Serial, Site / Location, Sources, Type, Status, Tags and Last seen, and switches between comfortable and compact rows. These choices are remembered in your browser only.

  • Click a column heading to sort by it; click again to reverse. Sorting, filtering and paging all happen on the server, so they cover the whole result and not just the rows on the page.
  • A value that is not known is shown as Unknown (or a dash), never left blank without a reason.
  • The page size is 50 rows by default and can be changed at the foot of the table.
  • Server vendor, model and serial are filled from the linked SNMP device when the agent has none. Servers otherwise show a dash there: the Windows agent in this release does not report a hardware identity.

02 Searching and filtering #

The search box matches text in the name, IP address, serial number, model, vendor, operating-system product and operating-system version. Press / to jump to it.

The filter pane groups the same choices as facets. Each choice shows how many machines it would give, counting the other active filters, so you can see the effect before you click.

FacetChoices
KindServer, Network device
OS familyWindows, Linux, FortiOS, PAN-OS, IOS XE, NX-OS, Junos, TMOS and so on, plus Unknown
OS / firmwareThe product within a family, for example Windows Server, FortiOS
Vendor, ModelAs reported or read from the device
Site / LocationA server’s site, or a device’s location text
TagsSeveral tags can be combined; a machine must carry every one
SourceAgent, SNMP, WMI, WinRM, SSH, Controller, ICMP
FreshnessFresh, Aging, Stale, Never, Not reported by design
Inventory healthThe eight checks described in health and freshness

Unknown is a real choice in the OS facets and is never hidden behind Show more. Active filters appear as chips above the table; click a chip to remove it, or Clear all filters. Filters combine with AND: a machine must match all of them.

On a narrow screen the filter pane becomes a drawer opened by a Filters button, and its footer button reads Show N assets.

03 Filters live in the address #

Every filter, the sort, the page and the open flyout are in the address bar. Copy the address and anyone with Inventory access sees the same list (limited, as always, to the assets their role covers). The Back button steps through your filters. The names are the same ones the Overview, OS, Software and Hardware pages use when you click a number, which is why those lists match the numbers you clicked.

ParameterMeaning
qSearch text
kindserver or device
os_family, os_product, os_release, os_versionOperating system level; the value unknown selects machines with none
vendor, model, siteExact match, not case-sensitive; unknown selects machines with no vendor or model
tagRepeatable; every tag given must be present
sourceagent, snmp, wmi, winrm, ssh, controller or icmp
freshnessfresh, aging, stale, never, not_applicable (not reported by design) or stale_or_never
healthOne of the eight health checks, for example missing_serial
product, product_versionServers that have a software product (by its product key), optionally one version; versions are compared by value, so 7.2 also finds 7.2.0
security_agent, cpu_model, memory, disks, virtualization, module_class, module_modelReached from the Overview and Hardware pages and shown as chips, not as facets. security_agent is present, missing or unknown and means endpoint protection
sort, order, page, page_sizeSorting and paging; page_size up to 500
assetThe open flyout, written server:<id> or device:<id>

A value the page does not understand is ignored and listed in a yellow notice, Ignored in the address, rather than silently changing the list.

04 The asset flyout #

Click a row (or focus its name and press Enter) to open the flyout, a panel on the right. The address gains ?asset=…, so the panel can be shared and survives a reload. There is no separate asset page: the existing server and device pages remain the detail pages, linked from the flyout.

Header
The kind (server or network device), status, IP address and the freshness badge, with links to the machine’s own page when you may open it.
Identity
Vendor, model, serial number, operating system or firmware (family, product, release, version, build and edition), each with a source badge and the age of the value. Raw evidence expands to the unprocessed text the device or agent reported, so you can see how a value was normalised.
Hardware (servers)
CPU model and core count, memory, disks, architecture and, once reported, virtualization.
Software (servers)
How many titles the server has (and how many are in hidden categories), a endpoint protection pill (present with the products and services that count, no endpoint protection found, or unknown with the reason), and up to ten titles with their versions, security products first. Each title with a catalog entry links to its product page. View all N on the server page opens the full list. If the list was cut at the agent’s cap, a note says so.
Device, High availability, Modules (network devices)
Profile, group, type and sysObjectID; for clustered firewalls the mode, role, peer and sync state; and the chassis, modules, power supplies and fans read from ENTITY-MIB, grouped by class and model, each expandable to its components and serial numbers.
Recent changes
The latest ten changes of this machine, with View all N opening the Changes page filtered to it.
Placement
The server’s site or the device’s location, and its tags.

05 Where a value came from #

A small badge beside each identity value says which collector supplied it. The tooltip adds the age. For network firmware, several sources can know the version; the most exact fresh one wins.

BadgeMeaning
AgentReported by the Windows agent on the server
TemplateRead by a vendor monitoring template (for example the exact FortiOS version of a FortiGate), within the last 24 hours
SNMP profileRead from the device’s system group and matched to a device profile
ENTITY-MIBRead from the chassis information the device publishes
sysDescrParsed out of the device’s own description text
Template (old)A template value more than 24 hours old, kept only because nothing fresher exists, so a device that was unreachable for a day keeps its last known firmware
ManagedReported by the controller that manages the device
Unknown sourceThe value exists but its source was not recorded

The order of preference for a network device’s version is: a fresh template value, the device profile, the chassis firmware, the version found in the description text, and last an old template value.

06 Opening the server or device page #

The flyout header offers Open server page or Open device page (and, for a server that is also an SNMP device, Open SNMP device page). The links appear only if your role holds servers.view or devices.view. Without that permission the entry is shown locked, with the permission named, so you know what to ask for. Seeing an asset in Inventory never gives access to its page.

“Asset not found” can mean two things

An address that names a machine that was deleted, or one outside the assets your role covers, opens a panel that says Asset not found. Both cases look the same on purpose, so the message does not reveal whether a machine exists outside your scope.

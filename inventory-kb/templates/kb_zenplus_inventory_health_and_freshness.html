ZenPlus Inventory

Reading the health panel and freshness badges

Two things tell you whether to trust a number in Inventory: how recently each machine reported, and what is still missing. This article explains the freshness badges, the line under the tabs and the checks of the Inventory health panel, and what to do about each.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators Reading time ~8 min

On this page

  1. Freshness badges
  2. The line under the tabs
  3. The Inventory health panel
  4. The endpoint-protection line
  5. Using the checks as worklists

01 Freshness badges #

Every asset has a freshness badge: a small pill with a word and, except for Never and Not reported by design, the age of its last inventory, for example Aging · 6h ago. The word is always written out, so the badge never depends on colour alone. Badges appear in the Last inventory column of the Assets list and in the header of the asset flyout.

BadgeMeaningServer, by defaultNetwork device, by default
FreshInventory reported within its freshness targetWithin 24 hoursWithin 2 hours
AgingOlder than the target, but not for long24 hours to 7 days2 hours to 7 days
StaleNot refreshed for a long time; treat its values as possibly out of dateOlder than 7 daysOlder than 7 days
NeverThe asset can report an inventory and none has been recordedAn agent server with no inventory reportA device polled over SNMP with no successful poll
Not reported by designThe asset cannot send an inventory and never has, so it is not a gapA server monitored over SSH, WMI, WinRM or SNMP only, or with collection offA ping-only device, or a child device managed through a controller

Not reported by design assets stay in the Assets list and are counted (filter freshness=not_applicable), but they are left out of Never, out of the fresh percentage, out of the missing-OS-version, -model, -serial and -vendor checks and out of the all-clear. The only way a server becomes Fresh in this release is the ZenPlus agent; a server monitored another way keeps this badge unless it reported before, in which case it carries a normal badge.

An age exactly at a boundary belongs to the fresher bucket. The targets are the defaults; an administrator can change them in Inventory settings, and every badge, filter and count follows at once.

Last inventory is not last seen

Hover over a badge. The tooltip separates two times:

Last inventory (data)
When the agent or the SNMP poller last refreshed this machine’s identity: operating system, hardware, software list. This is what the badge is computed from.
Last seen (reachability)
When ZenPlus last heard from the machine at all, by ping, heartbeat or poll. A server whose agent still sends heartbeats but no longer sends inventory has a recent last seen and an old last inventory.
Aging servers right after an upgrade are normal

The freshness time of a network device is set by its first successful SNMP poll after Inventory is installed, so devices read Never for a few minutes. A server that already held a software list is given the time of that list, so it shows its true age (Stale if it stopped reporting long ago). An agent server that never sent a list reads Never until its next inventory report, up to 6 hours with the default interval.

02 The line under the tabs #

Every Inventory screen shows one line directly under the tab strip, for example:

Inventory as of 14:05 · 94.4% fresh · 15 aging · 6 stale · 2 never reported · 8 not reported by design
  • Inventory as of is the time the figures were computed. The summary is recomputed at most once a minute.
  • % fresh is the share of the assets that can report that reported within their target. Assets that cannot report by design are not in the denominator. The percentage never rounds up to 100.0% unless every one of them is fresh. Click it for the list of fresh assets.
  • aging, stale, never reported, not reported by design appear only when they are above zero. Each one is a link to the Assets list with that freshness filter, and the list total equals the number shown.
  • When nothing is aging, stale or missing the line says every asset that can report did so within its target.
  • may be out of date with a Retry link appears if the last refresh failed; the figures are the last ones that loaded.
  • A Showing assets tagged … badge means your role or account limits you to those tags and every figure covers only the assets with them. See Permissions.

03 The Inventory health panel #

At the bottom of the Overview, Inventory health lists eight checks as a worklist, followed by one information line for the assets that are not reported by design. A check with a count above zero is a link: it opens the Assets list filtered to exactly the machines that fail it, and the list total is the number you clicked. A check at zero is shown with a tick and is not a link. When every check is at zero the panel reads Inventory is complete: every asset that can report did so within its targets and nothing is missing. That sentence never appears while the page says it is still normalising existing software lists.

CheckCountsUsual causeWhat to do
Assets missing an OS versionServers and network devices A server has not yet sent its operating system, or a device’s version could not be read or recognised For a server, check its agent is installed and reporting. For a device, check the SNMP credential and that the device is polled
Network devices missing a modelNetwork devices only The device did not answer ENTITY-MIB, or its description text does not name a model Make sure the SNMP view includes ENTITY-MIB (1.3.6.1.2.1.47)
Network devices missing a serial numberNetwork devices only The device does not expose a serial number over SNMP, or ENTITY-MIB is not answered As above; some platforms never publish one
Network devices with an unknown vendorNetwork devices only The device’s vendor identifier (sysObjectID) is not one ZenPlus recognises yet No device profile matches it yet. Note the sysObjectID shown in the asset flyout and send it to Zentryc support so a profile can be added
Assets with stale inventoryServers and network devices Nothing has refreshed the asset for more than the stale limit (7 days by default) The agent is stopped or the device no longer answers SNMP; the asset flyout shows both times
Assets that can report but never haveServers and network devices An agent server that never delivered an inventory report, or a device polled over SNMP that never answered Install or repair the agent, or fix SNMP reachability. Assets that cannot report by design are not in this check
Servers with a truncated software listServers only The agent sends at most 1,000 titles, sorted by name, and dropped the rest Nothing to fix; the titles beyond the cap are not counted anywhere in Inventory
Servers without endpoint protectionServers with a complete, processed software list and a service list No antivirus, endpoint-protection or EDR product is in the list and no Defender service is running. See the next section Check the server really has protection, then look at its software in the flyout
Why the model, serial and vendor checks ignore servers

The Windows agent in this release does not report a manufacturer, model or serial number for a server. Counting every server as “missing a model” would only be noise, so these three checks cover network devices only. Servers show their CPU, memory and disks instead.

04 The endpoint-protection line #

Under the Software titles figure on the Overview, and on the Assets page as the filter Endpoint protection, Inventory shows how many servers have endpoint protection, for example Endpoint protection on 39 of 52 servers with a complete software list (75.0%) · 13 without, and on its own line 3 servers unknown: no complete software or service list to judge. The covered number, the gap and the unknown line each open their own list of servers, and the three add up to every server.

  • A server counts as covered when its software list contains an antivirus, endpoint-protection-platform or EDR engine or sensor (the catalog category Endpoint protection: for example CrowdStrike Falcon, SentinelOne, Sophos, ESET, Trend Micro, Symantec, McAfee, Bitdefender, Kaspersky, Cortex XDR, Carbon Black, Malwarebytes, Cylance, Webroot, Avast and AVG), or when the Microsoft Defender Antivirus (WinDefend) or Defender for Endpoint (Sense) service is running on it. Built-in Defender has no entry in the list of installed programs, which is why the running service counts.
  • A server counts as without only when its software list is complete (not cut at the 1,000-title cap) and processed, and the server has reported a service list, and the two show no such product and no running Defender service. A server that already shows such a product counts as covered even when its list was cut: the cap only prevents the verdict without.
  • Every other server is unknown. It is in neither number and has its own line; the Assets list filters it with the chip Endpoint protection set to Unknown (no complete software or service list), and the asset flyout names the reason, one of four:
    • No software list has been reported for this server: a new agent, a server monitored without the agent, a server whose agent does not send software (Linux servers today), or software rows that Inventory never processes (rows with no source on a server that is not a Windows machine).
    • The software list was cut off, so protection cannot be judged: the agent stopped at its 1,000-title cap, and the product could be among the titles beyond it.
    • The software list is still being processed: right after an upgrade this lasts the minutes the existing lists need (see the first days).
    • Built-in Windows Defender can only be seen through the service list, and this server has not reported one: the list is complete and shows no protection product, but no service list exists at all (for example an agent set up for application monitoring only), so a running built-in Defender cannot be ruled out. It resolves when the agent reports its services.
    Only the third reason passes by itself. The others stay until the agent reports what is missing, and the screen does not promise that it will.
  • The number after of is covered plus without: the servers the question can be answered for.
It shows that protection is installed, not that it works

The line cannot tell whether a product is current, licensed, healthy or switched to a passive mode, and a protection product that the software catalog does not know is not counted until it is added to the catalog. Other security tooling is deliberately not counted: VPN and zero-trust clients, vulnerability-scanner agents, password managers, Sysmon, Wazuh and management agents are listed under Security, VPN clients such as FortiClient and Cisco Secure Client under Remote access, and the ZenPlus Agent under Monitoring; none of them counts. Open a server in the flyout to see which products and services made it count.

05 Using the checks as worklists #

Start with Never and Stale

Machines that are not reporting make every other figure less trustworthy. Open assets that can report but never have and assets with stale inventory first.

Then close the identity gaps

Missing OS version, model, serial number and vendor are usually one SNMP or agent problem per device. The flyout shows the source and age of each value and, under Raw evidence, the raw text the device reported.

Export the list

With the inventory.export permission, the Export button on the Assets page downloads exactly the filtered list. See CSV export.

Still unsure why a value is blank? See Troubleshooting.

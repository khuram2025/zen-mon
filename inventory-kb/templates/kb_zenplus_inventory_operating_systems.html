ZenPlus Inventory

Operating systems and firmware

Which operating systems and firmware releases run on your servers and network devices, how many of each, and how many are on the newest version you have. This article explains the tree, how a version is worked out, and what build currency does and does not tell you.

Applies to ZenPlus 1.24.0+ Updated 2026-10-09 Audience Operators Reading time ~6 min

On this page

  1. What the page shows
  2. Where the version comes from
  3. How versions are compared
  4. Build currency
  5. Unknown operating systems

01 What the page shows #

Inventory & Compliance → Operating Systems has a switch at the top: All, Servers or Network. The choice is kept in the address (?kind=server or ?kind=device).

The tree
Family, then product, then release, then version. Windows Server 2022 is a release of the product Windows Server in the family Windows; FortiOS 7.2 is a release of FortiOS. Each row has a count, a share bar and the number of distinct versions below it, and the newest version seen. Use Expand all and Collapse all, and click the column headings to sort. Where a firmware version was normalised from a longer string, a Reported as column shows the original text, for example v7.2.8,build1639,240614 (GA.M).
Every count is a link
Click a family, release or version count and the Assets list opens with those filters. Its total equals the number you clicked, including the Unknown rows.
Family donut
Shares by family, with the five largest families coloured, the remaining families folded into one grey slice, Other (N families), and a hatched Unknown slice. The grey slice covers several families, so it has no single filter and stays on this page; the legend beside the donut still lists every family as a link of its own. A View as table toggle shows the same numbers as text.
Build currency
One entry per release, described below.

The Export button (with the inventory.export permission) downloads the tree as a CSV, one row per version. See CSV export.

02 Where the version comes from #

ZenPlus stores the raw text every collector reports and never overwrites it. Inventory then normalises that text into a family, product, release, version, build and edition, using rule packs that ship with ZenPlus. Because the raw evidence is kept, an improved rule re-reads old data without losing anything, and changing the rules never creates change history.

Servers

The Windows agent reports the operating-system name, version and build. A name such as Microsoft Windows Server 2022 Datacenter with version 10.0.20348.2700 becomes family Windows, product Windows Server, release 2022, version 10.0.20348.2700, edition Datacenter.

Network devices

Network firmware is harder, because every vendor writes it differently. For each device the best available source wins, most exact first:

  1. a fresh vendor template value (FortiGate, Palo Alto and F5 report the exact version this way);
  2. the device profile: the version extracted from the device’s description text by its matching profile;
  3. the chassis firmware published through ENTITY-MIB;
  4. a version found in the device’s own description text;
  5. last, an old template value (older than 24 hours), used only so that a device that was unreachable for a day does not lose its firmware.

The asset flyout shows which source won, as a badge beside the version.

03 How versions are compared #

Two spellings of the same version are one version: 7.2 and 7.2.0 are counted together (trailing .0 parts are ignored), product and release names are matched without regard to case, and the label shown is the longer or most common spelling. A click on a version count therefore opens a list of exactly that many machines.

“Newer” is decided with the version rules of each product family, not by comparing text: 10.0.20348.587 is older than 10.0.20348.2700, 17.9.4 is older than 17.9.4a, and 11.1.2-h3 is older than 11.1.2-h10. Windows builds, FortiOS, PAN-OS (with hotfixes), Junos, IOS and IOS XE each have their own rules.

ZenPlus refuses to guess

Two versions from different release trains of classic Cisco IOS cannot be ordered reliably. When a release contains versions that cannot be compared, Inventory shows them in natural order without a “newest” verdict, and the build currency of that release reads No usable version, rather than showing a wrong ranking.

04 Build currency #

For each release, the Build currency panel splits its machines into four groups:

GroupMeaningA link?
Latest observedOn the newest version found on your own machines of that releaseYes, to those machines
N-1On the version just before itYes
OlderOn a version two or more places behind the newest observed (the third newest version or any earlier one)Text; several versions have no single filter
No usable versionNo version reported, or one that cannot be orderedText

The four groups add up to the number of machines on that release. Their bars use different shades and are labelled with words and counts, so they do not depend on colour.

“Latest observed” is not the vendor’s latest release

It is the newest version found on your machines. If every server is on an old build, they are all “latest observed”. This release does not compare against the vendor’s own lifecycle data, so treat build currency as a measure of how far your estate has drifted from itself; the page says so beside the panel.

05 Unknown operating systems #

A machine whose operating system could not be identified is in the family Unknown, always listed last and always counted, with a hatched slice in the donut. Click it to see which machines they are. Typical reasons are a server that has not reported yet, a server registered without the agent, or a device whose description text is not recognised by any profile. The Troubleshooting article walks through each.

# ZenPlus appliance security audit and remediation

Date: 6 September 2026. Controller: `192.168.8.221`. Deployed VMware probe: `192.168.18.128`, VMware-Probe-01, Riyadh. Assessment performed against the running appliance and its application source. This is a targeted engineering security review with remediation and regression testing, not an independent penetration-test certification.

**Result:** Confirmed application and management issues below were fixed on the controller. The deployed probe continues reporting. The management IP allowlist is implemented and deliberately **disabled/open by default**, as requested. Production security approval remains conditional on the outstanding items below.

## Implemented fixes

| Area | Finding before remediation | Change deployed / evidence |
|---|---|---|
| Management access | No administrator-configurable source restrictions | Added separate web and SSH restriction switches plus IPv4/IPv6 IP/CIDR list in Settings → General → Security. Admin-only API, CIDR validation, self-lockout prevention, root-owned policy, persistent firewall helper. Both switches remain OFF and the list empty. Verified save succeeds; invalid CIDR returns 422 and excluding the current administrator returns 400. |
| Internal network exposure | API, health listeners, legacy web and development ports reachable externally | API 8000, poller health 8081, NetFlow health 8091 and legacy web 8001 bind locally. IPv4/IPv6 firewall also blocks external TCP 8000/8001/8081/8091/5174. The separate development worktree remains running. Network tests confirmed those five ports blocked; 22/80/443 remain reachable. Monitoring listeners remain available. |
| TLS and browser controls | SPA/assets did not inherit security headers | Corrected nginx header inheritance, enabled CSP, nosniff, frame protection, referrer and permissions policies; retained HSTS and HTTP redirect. Network handshakes reject TLS 1.0/1.1 and accept 1.2/1.3. Certificate verification passed using the appliance certificate as an explicit trust anchor. |
| Sessions and passwords | Unthrottled login, 24-hour sessions, no server-side logout/password revocation, short new passwords | Added per-account and per-source login quotas, login audit events, one-hour tokens, database-backed session revocation, and 12-character minimum for new/reset passwords. New bcrypt-SHA256 password hashes avoid bcrypt's 72-byte truncation. Logout signs out all sessions for that account. Password, role, account-state and scope changes revoke existing sessions. Existing passwords were preserved. |
| Authorization | Missing credentials returned misleading 403; management protection needed validation | Missing credentials now return 401. Live disposable viewer account received 403 for management settings and saved SNMP credentials. The disposable account was removed after testing. |
| Stored secrets | Device communities and notification configurations stored in plaintext; LDAP/RADIUS secrets lacked encryption | Added AES-256-GCM envelopes for SNMP community/passphrase text, LDAP/RADIUS secrets and complete notification configurations, including URL/header/template secrets. Migrated 13 device community fields, two notification gateway configs and legacy SMTP/SMS settings transactionally. Stored SNMP credential/provider rows were absent or empty. Post-migration queries found zero plaintext device communities and zero unencrypted notification gateway configs. |
| SNMP credential handling | Secrets exposed through process arguments and regular device responses | Net-SNMP secrets now use a temporary 0600 configuration inside a 0700 directory, removed after the check. Regular device/credential responses mask communities; explicit administrator secret retrieval remains audited. Go poller and probe configuration delivery understand encrypted storage. On-demand Cisco fixture SNMP succeeded; scheduled controller cycle completed 12/12 successfully. |
| AD/LDAP | No explicit certificate validation; plaintext LDAP and failed StartTLS could proceed | Require LDAPS or successful StartTLS before bind, verify server certificates/hostnames, support an enterprise CA PEM, disable referral following, and reject ambiguous user searches. Tests prove failed StartTLS never sends a bind. LDAP is disabled/unconfigured, so no live directory login was performed. See [ldap3 TLS documentation](https://ldap3.readthedocs.io/en/latest/ssltls.html). |
| RADIUS | Missing Message-Authenticator protection | Requests include Message-Authenticator; unauthenticated/invalid replies fail closed. Local packet tests cover acceptance of authenticated replies and rejection when missing. RADIUS is disabled/unconfigured; no live RADIUS server tested. |
| Outbound integration TLS | Notification clients bypassed certificate checks; SMTP contexts did not explicitly verify certificates | Notification HTTP delivery now requires HTTPS with verification. SMTP uses verified implicit TLS or StartTLS before login/delivery. WinRM HTTPS validates certificates; HTTP WinRM requires message encryption. Configurations relying on plaintext gateways or untrusted certificates now fail closed and require remediation. Existing notification gateways are disabled, so no external messages were sent. |
| Administrative SSH | Root SSH, X11/agent/TCP forwarding and permissive authentication settings | Controller and deployed probe now disable root SSH and forwarding, reduce login grace time and authentication attempts. Password authentication remains available for the existing named administrators. SSH configuration validation and a fresh controller SSH connection succeeded. |
| Device SSH / Telnet | Automatic trust of unknown device host keys; plaintext Telnet credential probing | Require verified SSH host keys in `/etc/zenplus/known_hosts`, disable RSA/SHA-1 negotiation, reject Telnet collection/probing. Administrators must verify and install device host keys before SSH discovery/configuration backup can connect. No device host keys were guessed or automatically trusted. |
| Privileged operations | Broad raw LVM sudo commands; writable root-executed source and environment | Replaced raw LVM grants with a fixed helper that validates verbs, flags, fields and block devices. Valid reporting works; `--config` is rejected. Protected updater/support/helper sources and runtime ownership; `.env` and TLS private key are root-only 0600. Storage resize itself was not performed. |
| Logging and bootstrap | Query strings could expose SSE tokens in access logs; console passwords appeared in generated cloud-init | nginx logs omit query strings, and uvicorn request access logging is disabled. Newly generated probe seeds contain a salted SHA-512 password hash instead of plaintext and install SSH hardening on boot. The running probe is separately hardened. Existing seed media should be detached and protected/disposed of according to the organization's credential-handling policy. |
| Dependencies | 64 advisory records across 12 Python packages; frontend vulnerable dependencies | Replaced python-jose with PyJWT and upgraded affected Python/web packages in a separately built runtime. `pip check` passes. Final Python scan has one remaining advisory; final npm scan has zero. Counts are scanner advisory records, not independent exploitable paths. |

TLS and secret-storage controls were reviewed against the [OWASP TLS guidance](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html) and [OWASP secrets-management guidance](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).

- Ubuntu package metadata refreshed successfully. The configured Ubuntu unattended-security-upgrade dry run reported **no eligible pending packages**. General release updates remain available; container images and a full OS benchmark were not comprehensively audited.

## Outstanding items for security approval

1. **Change the existing controller/admin passwords before production.** They were explicitly left unchanged at the owner's request. Prefer named accounts and SSH keys; disable SSH password authentication after key access is validated.
2. **Establish enterprise trust.** The current HTTPS certificate is self-signed for IP `192.168.8.221`, valid until 22 August 2029. Install an enterprise-issued certificate with the intended DNS/IP SANs and distribute its CA to browsers, probes and agents. AD/WinRM/SMTP/webhook certificates need their appropriate trust chains too.
3. **Configure the management allowlist.** Currently OFF by instruction. Add the approved administrator/VPN subnets, include the current source, then enable the applicable switches. Keep VM console access for recovery. Existing SSH sessions are retained when restrictions change; new sessions are filtered.
4. **MFA is not implemented by this patch.** Define the organization's MFA requirement and implement/enforce it through an appropriate authentication design before approval if required. LDAP alone does not provide MFA. Validate directory group-to-role mappings and least-privilege service accounts with the real AD/RADIUS environment.
5. **Migrate legacy device/service transports.** SNMPv1/v2c communities remain plaintext on the device network despite encrypted storage. Use SNMPv3 authPriv with modern algorithms where supported. The tested NTLM service target is HTTP; move it to trusted HTTPS or explicitly accept the segregated-network risk. Credentialless discovery may inspect untrusted HTTPS sites to identify devices; that exception is distinct from credential-bearing integration transport.
6. **Track the Paramiko exception.** `PYSEC-2026-2858` / `CVE-2026-44405` remains in Paramiko 4.0.0. Version 5 removes RSA/SHA-1, but Netmiko 4.7.0 declares `<5.0`; installing both fails dependency validation. Appliance SSH call sites disable `ssh-rsa` and require trusted host keys as mitigation. Upgrade the compatible dependency pair when available and rescan; do not describe the Python inventory as vulnerability-free. See the [Paramiko 5 changelog](https://www.paramiko.org/changelog.html).
7. **Complete deployment governance.** Obtain independent security review, audit-log retention/forwarding requirements, backup encryption/key escrow, recovery testing, and any required OS/container vulnerability scans. These controls were not certified here. Integrate this source patch into the approved controller release before allowing an older/unpatched OTA release to overwrite it.

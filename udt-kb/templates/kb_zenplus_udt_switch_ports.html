Switch ports, uplinks and capacity

A live port map per switch: what is plugged into each port, which ports are uplinks, which are free, and whether you are about to run out.

01 The port map #

The rail on the left lists every switch UDT has port data for, each with a utilisation bar and three counts: free, uplinks and active (ports that carried an endpoint in the last 24 hours). Selecting one loads its ports.

Port / Description
Interface name and the alias configured on the switch — the patch-panel label, if your team maintains descriptions.
Status
up, down, or admin down for a port that is administratively shut.
Speed / VLAN
Negotiated speed and the VLAN the port's endpoints were learned in.
Endpoints
How many endpoints currently hold an active session on this port. Click the number to list them.
Role
access or uplink, with the reason for the verdict.
UDT
Whether this port contributes endpoints at all — see excluding ports.
Last device
When an endpoint was last seen here. This is the column that tells you a “free” port was in use last month.
Finding a genuinely free port

Sort by Last device. A port that is down and has never carried an endpoint is free. A port that is down but had a device last week is probably a desk whose occupant is on leave — reclaiming it will generate a ticket.

02 How uplinks are detected #

Separating access ports from uplinks is what makes UDT useful rather than noisy. Without it, every MAC in the building appears on every trunk. UDT decides automatically on each poll, first match winning, and shows you the reason:

ReasonEvidenceReliability
lldp / cdpThe neighbour on this port is another monitored device, or advertises itself as a switch, router, firewall or a network OSHighest — the port is talking to infrastructure
trunkCisco VTP reports the port as trunkingHigh, Cisco only
mac_countEight or more distinct MAC addresses learned on one portGood, but see below

The MAC-count rule is the fallback and the one that occasionally misfires in both directions. A desk with an IP phone, a laptop behind it and a docking station stays well under the threshold and is correctly access. A port feeding an unmanaged desk switch, a virtualisation host with many VMs, or a wireless access point serving a busy area will exceed it and be called an uplink — sometimes rightly, sometimes not.

Every port on a switch is an uplink

On a core or top-of-rack switch whose every port faces other infrastructure, this is correct and expected — the switch has no access ports, so it contributes topology rather than endpoints. On an access switch it means the LLDP neighbour identity is being misread; check the neighbour data before overriding ports one by one.

03 Overriding the verdict #

The arrow icon in the Actions column toggles a port between uplink and access. An override is sticky: once set, the automatic classification never runs on that port again, so a virtualisation host port you have marked as access stays access no matter how many VM MACs appear on it.

Overrides change what UDT calls direct, so they take effect on the next poll and reshape the endpoint list for every device behind that port. Two common cases:

  • Force to access — a hypervisor NIC, a port feeding a small unmanaged switch you do not monitor, or an access point whose clients you want attributed to that port.
  • Force to uplink — a link to a switch you do not monitor, which has no LLDP neighbour to identify it and too few MACs to trip the count rule.

04 Excluding ports from UDT #

The UDT toggle on each row controls whether that port produces endpoints. Turn it off and the port keeps reporting its status, speed and MAC count — so it still counts toward capacity — but it stops creating endpoints, sessions and events. Any active sessions on it are closed immediately rather than waiting out the 15-minute grace period.

Select several ports with the checkboxes to apply Include in UDT or Exclude from UDT in bulk.

Use it for ports whose endpoint churn is noise rather than signal: a lab segment, a guest VLAN uplink, a span or monitor port, or a link to a third-party network you do not administer.

05 Shutting down a port #

The power icon shuts down or re-enables a port. It sends an SNMP SET to ifAdminStatus on the switch, so it needs a write-capable SNMP credential — see remote port control. ZenPlus confirms before sending, naming the switch and the port.

  • Requires the operator role.
  • Success and failure are both written to the audit log with the operator's name and the SNMP error, if any.
  • A port action event appears in the UDT activity feed.
  • Without write access the action fails with an SNMP error — nothing on the switch changes.
Check the role before you shut

Shutting down a port marked uplink disconnects everything behind it. The role column is right next to the action for exactly this reason.

06 Capacity planning #

UDT records a capacity snapshot per switch once a day, kept indefinitely, so port growth is a trend rather than a guess. Each snapshot holds four numbers:

Total ports
Physical Ethernet interfaces. Virtual interfaces, SVIs and aggregates are excluded so the count matches the sheet metal.
Used ports
Ports whose operational status is up. This is the number that drives utilisation.
Active ports
Ports that carried an endpoint in the last 24 hours — a stricter measure than “up”, since a port can be up with nothing behind it.
Uplink ports
Ports classified as uplinks, which are capacity you cannot sell to a desk.

The gap between used and active is usually the interesting one. A switch at 80% used but 40% active has a lot of ports that are up with nothing on them — patched but unoccupied — and can often be reclaimed without buying anything.

Alerting on port exhaustion

Create an alert rule with the metric udt_port_capacity_pct under Alerting → Alert Rules. Unlike the other UDT metrics, this one is a genuine threshold with automatic recovery: it raises when a switch crosses the percentage you set and resolves by itself when utilisation drops back. Scope it to a device, a group, a device type or a location, or leave it global to cover the estate.

Pick a threshold you can act on

90% of a 48-port switch is five free ports — enough warning to order hardware, not enough to survive a floor move. If lead times are long, alert at 80%.
